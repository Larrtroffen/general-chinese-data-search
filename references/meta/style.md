# style —— 源卡与索引的写法规范

目标：任何一个文件拎出来都像**同一本书的一页**——标题短、字段固定、事实有出处、不含「某个第三方 skill 的说明书」痕迹。

## 一、文件命名

- 一源一文件，文件名 = **规范名**：优先域名（`modernhistory.org.cn.md`）；无域名用简短服务名（`data_location.md`、`kanripo.md`）。
- 不出现仓库所有者前缀（`changwu/…` 写进「上游」行）、不出现 `（合并卡）` `（付费）` 之类括号。

## 二、卡片骨架（字段顺序固定）

```markdown
# <规范名> —— <一句话定位，≤18 字，不复述名称>

- 去哪找：入口/检索页/API 的 URL（可给 1–3 条）
- 什么时候用：会触发查这里的需求（关键词式列举）
- 怎么搜：最小可复现操作（URL 模板 / curl / 参数表）；结果形态（HTML / JSON / 需登录 / 需浏览器）
- 覆盖：范围 · 年代 · 粒度 · 更新频率
- 门槛：免费 / 注册 / 订阅 / 单位 IP / 验证码 / 需 key（无则写「无」）
- 实测：YYYY-MM-DD，命令或 URL + 观察（状态码/标题/命中）
- 上游：来源链接（repo / 公告 / 渠道）

## 细节        ← 需要时才加（端点表、字段表、代码块）
## 坑          ← 需要时才加（反爬、编码、时效、版权）
```

- 字段名逐字固定；用 `-` 列表，不用表格承载主字段（表格只放 `## 细节`）。
- 不能"搜"的语料/仓库类源，`怎么搜` 换成 `怎么取`（仍保持此顺序位）。
- 未本机验证一律在句中标注「（上游声明，未本机实测）」；实测过的给命令与观察。
- 日期用 ISO（`2026-10-03`）；状态符号只用 `✅/⚠️/❌`。

## 三、标题规则

- 规范名用中文或域名，避免英文动词短语；定位语不重复名称里的信息。
  - ❌ `# tmwgsicp/wechat-download-api —— 微信公众号后台凭证 HTTP API（AGPL）`
  - ✅ `# wechat-download-api —— 公众号后台凭证采集`
- 去掉冗余修饰（"一站式""合集""Skill""MCP Server"等）——它们是渠道属性，放「门槛/细节」里。

## 四、层索引（每层 README.md）

- 固定三段：`文件一览`（表：文件 · 来源 · 用途/何时用 · 状态）、`选路`（什么时候用哪个，3–6 条）、`相关`（跨层链接）。
- 表格列名与顺序全库一致；状态列只放 `✅/⚠️/❌ + 最多 6 字`。

## 五、与其他文档的关系

- 顶层 `SKILL.md`：只讲「怎么用这个库」与分层总表，不重复卡片细节。
- 根 `CANDIDATES.md`：只放未收编候选与进度；已收编项标 `已收编→<文件>`。
- 转写 = 只动**结构与措辞**，不动事实：不新增断言、不删实测数据、不改日期与链接。
